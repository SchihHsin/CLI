00  需求定义与整体流程
1
用户发起长耗时 Bash，例如 npm run dev、pytest -q、tail -f app.log、构建/部署/监控类命令
2
命令直接开始运行；需要非阻塞执行时，后台命令立即返回命令 ID，不弹窗询问，也不提供转前台入口
3
后台命令被赋予稳定 ID，输入框立即恢复，用户可继续向 Agent 提需求
4
后台命令的 stdout/stderr 不再刷屏，而是进入日志缓冲区；TUI 在对话流内展示当前命令分区和管理提示，完整日志在独立弹窗查看
5
用户通过 /task、状态栏命令 chip、或通知唤起后台命令弹窗，查看输出、停止、重跑、附加摘要
01  步骤一 · 后台命令直接启动
1
用户输入会启动长驻进程的 Bash 命令。命令直接在后台运行，不弹选择框，立即返回命令 ID。

04  步骤四 · 前台 Bash 超过 15 秒，提示可转入后台
4
Bash 已运行超过 15 秒仍未结束。系统只给出非阻塞提示，告诉用户可以按 Ctrl+B 转入后台；不会自动切换，也不会提供转回前台入口。

06  交互规则与边界
Claude Code 对齐检查：后台 Bash 直接运行或按 Ctrl+B 放到后台，返回命令 ID；后续动作收敛为查看日志、停止、重跑、附加摘要，不提供转回前台；长时间前台执行只提示可按 Ctrl+B，不自动转后台。
模块规则交互表现
触发方式命令直接运行，或用户输入 /bash --bg、按 Ctrl+B直接返回命令 ID，输入框立即恢复，不弹执行方式选择
运行态动画运行中的 Bash 行前使用 Braille spinner，按 ⠋ ⠙ ⠹ ⠸ ⠼ ⠴ ⠦ ⠧ 循环命令行显示为 Bash(npm run dev)，浅灰底；下方深灰底显示 Running in the background (/task to manage)
前台转后台前台 Bash 执行超过 15 秒仍未结束，且进程仍存活或持续输出只提示可按 Ctrl+B 转入后台，不自动切换
日志策略stdout/stderr 进入输出缓冲；列表不展示输出，详情视图按需读取按 Enter 进入独立输出视图
上下文策略默认只把摘要给 Agent；完整输出需用户确认附加按 A attach summary，避免污染上下文
中断规则Ctrl+C 只取消当前前台输入，不杀后台命令停止命令必须在 /task 弹窗里按 S 二次确认
资源保护限制同时运行数、空闲时长和最大运行时间超限时命令状态变黄，提示清理或延长
危险命令涉及删除、部署、写系统路径、外网传输等仍走原权限确认后台执行不降低安全门槛
